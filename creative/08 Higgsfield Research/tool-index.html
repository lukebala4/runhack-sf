ads_studio_add_product

Add a product to Ads Studio - under a brand, or with no brand at all - from its page link and/or a pasted description. Answers as soon as the row is queued - Ads Studio reads the page in the background. Do not poll and do not list products to check. Read ads_studio_get_product when the user asks about it. Use this when the research missed a product or the user names a new one. To refresh an existing product from its page, pass its id in overwrite instead of adding a second row.

ads_studio_cancel_run

Cancel a queued or running Ads Studio generation. Pictures already rendered stay; a run too far along to stop answers that it can no longer be canceled. Only cancel when the user asks.

ads_studio_create_brand

Research a brand from its website and build its Ads Studio brand profile: products, palette, logo, tone and audience, read from the live site. Pass the website when you have it - with a URL the research starts at once and takes a few minutes; with only a name Ads Studio answers with the site it thinks was meant and starts nothing, so confirm that with the user and call again with the URL. This reads the brand's own public website. It does not design logos or brand assets (that is the brand-asset-creation workflow) and it is not the Marketing Studio brand-kit record (marketing_create_brand_kit). Before the first Ads Studio call in a conversation, load the Ads Studio instructions with get_preset_instructions and preset 'ads-studio'.

ads_studio_generate

Generate ad creatives in Ads Studio: for a brand, for products of any brand or of none, or from a prompt and the user's pictures alone, with or without the brand kit. Ads Studio writes the concepts and renders the pictures. This spends Higgsfield credits, so quote with ads_studio_quote and get explicit approval of the exact allocation and credit cost first. An approval from the Ads Studio app allocation is NOT approval. When allocation is supplied, this tool quotes the whole allocation and requests native MCP form confirmation when supported. Otherwise it returns approval_required and credits: show the exact counts and cost, ask for explicit chat approval and stop. Only after approval, repeat the unchanged allocation with expected_credits. Never split the allocation or bypass a supported native form. Answers as soon as the runs are accepted, with a run id each - report those and stop; read ads_studio_get_run when the user asks, never in a loop. Generation takes a few minutes.

ads_studio_get_brand

Read one Ads Studio brand: how far its research got through the five stages (gather, synthesis, enrichment, products, assets) and what is already usable. Use this to answer "is the research done?" - status done means the brand and its products are ready. Call it when the user asks, not on a timer, and never in a loop: research can take several minutes. Follow next_step: a finished research is offered for ads, never generated on its own.

canvas_add

Add items to an existing Higgsfield canvas board in the authenticated user's workspace: sticky notes, text, shapes, images, image and video generation nodes, and connections between items. It does not create pages; page_id puts an item on a page that is already on the board. Use it when the user asks to put something on a board; canvas_update changes existing items and canvas_remove deletes them. Added items are saved to the board and appear live for everyone viewing it, including an open_canvas view already shown: do not call open_canvas again to refresh it. A generation item saves its model, prompt and settings only: this tool does not start generation or charge generation credits; canvas_run does. Give a generation item only the settings the user asked for: the others stay the model's defaults, and the result lists the settings each generation node got and any value the model did not take. An image item imports a Higgsfield generation or upload image URL into the user's Higgsfield media; unsupported URL origins are rejected before the board changes, and imported media may remain even if adding to the board fails. A connection into a generation node feeds it: the source (an image, a video, another generation node's result, or text for the prompt) fills the node's matching free input (an image fills reference images before a start or end frame; set the connection's input to choose, e.g. start_image for an exact first frame), and canvas_run uses it. That is how to generate from an image on a board, e.g. image to video. Between other items a connection draws an arrow. Give items a key to connect them in the same call; connect to items an earlier call added by the ids it returned. To add more than 5 items, make several calls of up to 5 items each, in the order a person would lay them out (a card or a step at a time), so everyone viewing the board sees it grow, and set final on your last change to the board. Additions can partially apply: inspect applied and rejected before retrying, since repeating an addition creates duplicates. Returns the new items' ids in order, and each connection's id and the input it fills.

Only `succeeded`, `failed`, `timed_out`, and `expired` are terminal; all other statuses require another poll using the same project and operation IDs. An HTTP success or a wait timeout does not mean the operation finished. Do not submit another mutation while one is active. On success, use the returned revision and scene sequence for subsequent work; obtain published images and videos through `scene_builder_3d_get_artifact`. On failure, inspect the error and re-read project state before deciding to retry. Do not blindly resubmit a failed operation under another ID.

scene_builder_3d_get_project

Read a 3D Jutsu project's current revision, scene sequence, active operation, and committed artifacts. Obtain `projectId` from `scene_builder_3d_list_projects`, `scene_builder_3d_create_project`, or an explicit user selection. An authorized project with `exists: false` is a valid empty scene at revision 0. Use `scene_builder_3d_query_python` to inspect actual objects, dimensions, materials, cameras, and lights before editing. If an operation is active, use `scene_builder_3d_get_operation` to settle it before another mutation. Scene edits use `scene_builder_3d_run_python` with the exact revision and scene sequence inspected; never guess these guards.

scene_builder_3d_import_asset

Import a confirmed catalog GLB from `scene_builder_3d_search_assets` into the selected project as a collaborative scene entity. Supply the catalog's asset ID, not a URL. The tool runtime resolves and uploads the bytes, reads the project guards, submits the import, and waits for it to appear in the settled scene. Do not import while another mutation is active. After import, inspect dimensions, placement, orientation, contact, and materials with `scene_builder_3d_query_python` before further edits. Do not repeat the whole import to poll: it can create a duplicate. If an import fails, report the error; never fall back to Python network calls or base64-encoded model bytes. Copy catalogSearch from the search result's importArguments. If settled is false, poll scene_builder_3d_get_project until appliedSceneSequence reaches targetSceneSequence. If submissionUnknown is true, inspect the returned entityId before deciding to retry. This version accepts catalog assets only.

scene_builder_3d_list_generations

Read the shared image/video generation history of a 3D Jutsu project, newest accepted first. Includes pending and failed attempts. Pass nextCursor as before for older records; status changes never reorder records. Use scene_builder_3d_get_generation for an individual result.

scene_builder_3d_list_projects

Discover the authenticated user's 3D Jutsu projects before choosing a scene to read or edit. Follow `nextCursor` to see more results. Use the selected project's `id` as `projectId` in every project-scoped 3D Jutsu tool; no call sets a global active project. Match the user's named project, and ask them to choose if the result is ambiguous. Then call `scene_builder_3d_get_project` for its current state. A project's presence here does not bypass permission checks on subsequent calls. To start a new project, use scene_builder_3d_create_project.

scene_builder_3d_query_python

Inspect the latest settled Blender scene without committing changes. `bpy` and the `artifacts` registry are available; assign concise JSON-serializable findings to `result`. Query exact names, metre-scale dimensions, transforms, parents, collections, materials, cameras, lights, visibility, and animation settings as needed. Inspect Blender RNA when an API or enum is uncertain. Temporary scene changes are discarded, including camera changes used for inspection. A query can render and publish images for visual inspection: allocate a target with `artifacts.file(name="preview.png", media_type="image/png")`, write the image to `target.path`, and call `target.publish()`. Resolve published IDs with `scene_builder_3d_get_artifact`. Use the successful query's `revisionBefore` and `sceneSequenceAfter` as the guards for the next `scene_builder_3d_run_python` call. If still active, poll `scene_builder_3d_get_operation`. Reuse an operation ID only to retry the identical request. Imported model bytes must enter through `scene_builder_3d_import_asset`; do not fetch URLs or embed file bytes in Python.

scene_builder_3d_run_python

Commit one coherent Blender scene edit against the exact revision and scene sequence you inspected with `scene_builder_3d_get_project` or `scene_builder_3d_query_python`. `bpy` and `artifacts` are available; assign JSON-serializable findings to `result`. Keep one mutation active per project, including imports. If this operation remains active, poll `scene_builder_3d_get_operation` before editing again. Reuse `operationId` only for the identical code and preconditions. On a stale-state conflict, inspect the scene again and regenerate the edit with fresh guards and a new operation ID. A successful mutation advances `revisionAfter`.

scene_builder_3d_search_assets

Search the curated GLB model catalog available to 3D Jutsu. This read is authorized against `projectId`; the catalog itself is shared. Pass a returned `assetId` to `scene_builder_3d_import_asset` for the same selected project. Search results are available models, not objects already present in the scene. Inspect existing scene objects with `scene_builder_3d_query_python` before deciding what to add. Never invent an asset ID or turn a catalog URL into Python download code. Copy the returned importArguments, including catalogSearch, into scene_builder_3d_import_asset.

scene_builder_3d_show_scene

Show an interactive 3D scene preview of an existing 3D Jutsu project. Choose projectId with scene_builder_3d_list_projects, scene_builder_3d_create_project, or the user's explicit selection. Pass revisionAfter from a successful edit to show that exact result, or omit revision for the latest committed GLB. Wait for edits to settle with scene_builder_3d_get_operation before showing their result. This reads an existing export; it never starts Blender, edits the scene, or includes uncommitted collaborative changes. Call this when the user asks to see the scene. For a completed scene creation, edit, or import task, call it once at the scene review boundary after settlement and verification. Do not repeat an unchanged revision. Authorized generation/status calls may follow; feedback or a verified mismatch can reopen editing and lead to a newly verified revision. The widget is for the user to inspect; it does not give the agent visual evidence. Use scene_builder_3d_query_python and scene_builder_3d_get_artifact for the agent's visual verification. If the client cannot display widgets, provide the returned projectUrl.

search_folders
