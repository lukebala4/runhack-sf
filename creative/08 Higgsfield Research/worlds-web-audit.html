Higgsfield: website, game, canvas and 3D capability audit

Checked 17 October 2026. Read-only investigation for the existing local Running Hackathon creative warehouse. No cloud project, board, website, generation or paid action was created; no Blender code was executed.

Decision

Higgsfield can materially help create the visual assets and motion for the field-plus-track direction. It also exposes genuine hosted 3D scene construction and a separate hosted website/app/game builder. Neither needs to replace the current local warehouse or the Rive character.

The strongest immediate use is a tightly directed set of image/film studies for the existing site: warm morning track meeting Swedish midsummer landscape, restrained real-world colour, brick-orange shoes, and simple prominent type added in HTML. An optional second use is more polished animal concept art and motion references. Keep the selected interactive mascot in Rive, because generated film or sprites do not supply its editable vector rig, state machine, gaze, native listeners or .riv export.

Three materially different approaches:

Approach Benefit Cost/complexity and risk Recommendation
Generate stills and short film assets; integrate locally Improves the visual material while retaining every current direction and the current runtime Generation credits; anatomy, footwear and continuity need inspection; video needs poster, compression and reduced-motion treatment Start here. It directly addresses the user's aesthetic complaint.
Build an editable 3D Jutsu track/meadow blockout, then render or use it as AI conditioning Repeatable camera placement, layout and lighting; a real editable source and portable scene export Scene modelling and visual QA are more involved; curated-model import restriction; exports can differ; AI appearance can still drift Use when exact camera/layout consistency across several views becomes important.
Create a new Higgsfield-hosted website, generation app or game Hosted infrastructure, app auth/generation SDK or game rooms/persistence Separate product and cloud codebase; direct live deploy; genre-catalog mismatch below; it does not automatically migrate the local warehouse Useful for a separately requested hosted product, not the default response to improving this local site.

What the connected tool surface actually exposes

Website, app and browser game builder

The installed website-builder skill describes React 19 + TanStack Start server-rendered projects, deployed as one Cloudflare Worker per product. Code editing is performed through the provided cloud sandbox; checkout/push access has a 15-minute editing lease. It is a scaffold-and-code workflow, not a one-call design generator. Deployment builds the pushed source and immediately changes the public live site. Community-feed publication is a separate operation; it does not deploy.

The three product types have different contracts:

Type Supported intent Relevant Running Hackathon idea
website Standalone branded website without user-facing AI generation or Higgsfield sign-in A separately commissioned marketing site with a generated morning film hero
app Users sign in with Higgsfield and generate via its SDK using their own credits; uses its Quanta UI shell A sponsor activation where attendees generate artwork, if that specific experience is wanted
game Browser game with rooms, sockets and persistence; single-player is allowed A timed sponsor relay, shared-room challenge or score game

The app starters are studio, preset, and app-detail; custom is reserved for an explicit request. The website starter can include a prebuilt scroll-scrub engine for a generated film controlled by scrolling. The skill also describes layered parallax, image particles, masks and other code-driven presentation effects. A scroll-scrub film is still rendered media being scrubbed: it does not become the reactive Rive character.

Game logic is specified as six pure functions (meta, setup, validateAction, applyAction, isGameOver, viewFor) with the platform owning room transport and persistence. The documented path is 2D, with image/video-derived sprite sheets and generated music, effects or voice. This can support the sponsor play area as a separate hosted game, but it is not required to improve the current local 2D relay.

Unresolved live mismatch: the game reference requires a game genre such as arcade, sports or endless-runner, and says list_website_categories supplies the valid genres. The live read returned only eight media-style categories: viral-trends, ads-marketing, ugc-social, cinematic, characters-avatars, product-ecommerce, portrait-lifestyle, other. The create_website metadata likewise refers to that shared category source. I did not create a throwaway game to test which taxonomy is accepted. A functioning game-creation path is therefore documented but not proven in this account.

Read-only management includes website listing/status, D1/SQLite tables/schema/rows/SELECT inspection, and configured secret names without secret values. The package describes D1/R2 and Durable Objects; the cloud sandbox and production share live resources rather than isolated staging data. The connector's secret tool does not set values; those are configured through website settings and applied on deployment. It is not a general unrestricted hosting or container provisioner.

Canvas as a creative board and generation graph

Canvas tools can create/open/read boards and add/update/remove sticky notes, text, shapes, images, generation nodes and arrows. A generation node stores model, prompt and settings without starting a generation. Connections feed text, reference images, start/end frames or upstream results into downstream generation nodes. canvas_run executes a selected graph including dependencies.

For this project that could become an optional visual workspace with columns for the five animals, field/track art direction, source references, selected shots and motion experiments. It is a useful collaborative cloud surface, while the existing 04 Creative Warehouse should remain the durable local review dashboard and provenance record.

Limits and operational details:

  • The exposed add call does not create board pages; page_id targets an existing page.
  • Board image imports accept Higgsfield generation/upload image URLs, not arbitrary Pinterest or local filesystem URLs. A media import can remain even if adding the board item fails.
  • New generation nodes do not run themselves. canvas_run(confirm=false) prices the graph without running it; confirm=true starts the priced generation after agreement.
  • Direct generate_image/generate_video outputs do not automatically land on a board. Use board generation nodes for an attached graph, or place the completed accessible media on the board afterwards.
  • Canvas changes are saved live. Adds can partially succeed and repeating them can duplicate nodes; read back applied/rejected results before retrying.
  • No general canvas export-to-local-dashboard or full automatic local/cloud synchronisation tool was exposed. Such synchronisation would need a separate implementation and policy for IDs, prompts, versions and media provenance.

Media project/library organisation

Media projects, hosted websites and 3D Jutsu scenes are distinct resource types with separate listing tools. A media project is not the user's local Running folder and is not automatically a website or scene.

The media project API supports accessible project/workspace discovery, metadata and folder inspection, paginated asset listing, prompt-only reads, source/download-detail reads, attachment, copy/move/remove, project updates, reversible archive/unarchive and deletion. Assets have typed source identities (job, media_input, video_input, audio_input, file_input) and placement IDs. Multiple placements can refer to one source. Copying a placement is not a new uploaded source; removing a placement is different from deleting the underlying file. Shared projects may belong to a workspace other than the request context.

That is useful for keeping generations associated with a named creative effort and retrieving their original prompts/source details. It is not proof of ingesting every pin from a Pinterest board, clearing reuse rights, deduplicating arbitrary external archives, or preserving local files automatically. The current local reference archive and catalog should remain intact.

3D Jutsu: real scenes, not just a 3D-looking picture

Current connected tools and the live /3d-jutsu recipe establish a hosted, revision-controlled Blender 5.2 scene system. It can inspect/edit geometry, semantic objects, transforms, parents, materials, cameras, lights, keyframes and constraints through bpy. The source scene is editable and successful mutations produce committed revision/scene-sequence receipts.

The scene system can:

  • Construct and edit a scene procedurally using the hosted Blender API.
  • Search a curated GLB catalog and import returned asset IDs into a selected project.
  • Render temporary previews without committing scene changes, or publish PNG/JPEG/MP4 artifacts from operations.
  • Deliver the committed portable .glb scene and editable .blend source through short-lived downloads.
  • Show an interactive preview of a committed GLB revision.
  • Generate an AI appearance image from an inspected scene render (3d_jutsu_angles, Seedream V5 Pro pricing) or a paid Seedance 2.5 video using supported reference roles. These generative steps leave the scene itself unchanged.

This could produce a coherent track curving through meadow, matching sunrise direction across several viewpoints, sponsor objects placed in a consistent scene, or a stylised mascot/prop turntable. It is a more controlled camera/layout route than asking an image model to rediscover the whole world independently each time.

Hard limits:

  • This version imports curated catalog assets only. It cannot import the user's own GLB/file into Jutsu. Runtime Python has no network access and must not embed uploaded model bytes as a workaround.
  • Search requires an authorised existing projectId. The account returned no existing Jutsu projects. Consequently animal/track catalog availability was not searched, and no exact asset should be promised.
  • The runtime pins Blender 5.2 and has an approximately five-minute operation deadline, 256 KiB code cap, and eight published PNG/JPEG/MP4 artifacts per operation. Long rendered animation is more constrained than authoring its keys. Timeouts commit nothing.
  • The recipe says .blend preserves authored animation. A full MP4 render is a stretch goal after still-frame proof. A Seedance clip from one render is separate generated motion, not evidence that Blender's keyed movement was faithfully rendered.
  • Procedural materials, world lighting and some Blender features do not reliably carry into GLB. Area lights are dropped by scene preview/GLB; camera renders and portable scene previews both require visual inspection.
  • Successful Python execution or a valid downloadable GLB establishes neither artistic quality nor correct geometry, lighting or contact.
  • No direct .riv export, Rive vector layer conversion, state-machine synthesis, bone/weight transfer to the current hare, or Rive runtime replacement is exposed here.

Reconciling contradictory documentation

The installed website-builder SKILL.md, its asset-system.md, wow-catalog.md and game-flow.md say the client cannot make image-to-3D assets and its game pipeline is 2D. The newer/current connected scene_builder_3d_* tools plus the live /3d-jutsu recipe explicitly support real hosted scenes and GLB/Blender exports.

These should be reported as different surfaces with a documentation inconsistency, not collapsed into either “Higgsfield cannot do 3D” or “the website builder automatically supplies full 3D games.” The live recipe also distinguishes standalone image-to-mesh generation from scene building. I did not verify any image-to-3D model or price in this sub-audit; the scene tools alone do not prove that pipeline. Preserve the game skill's 2D contract unless the platform provides an updated supported game path.

Likewise the website asset guide says there is no background remover/upscaler/uncrop on its builder surface. That is not evidence that those features are absent from every model or other Higgsfield tool. The overall report should compare the current model inventory separately.

Automation that is actually present

There are batch image/video/audio submissions, async job waiting/status, preset workflows, canvas dependency graphs, media-library organisation, scene mutation receipts/idempotency, and scripted cloud site editing/deployment. These are useful automation primitives. This tool inventory did not expose a recurring scheduler/watch service; it does not establish continuous unattended monitoring, a durable cross-run workflow orchestrator or automatic local-file sync.

For a larger concept library, retain stable study IDs, the exact model/settings/prompt and references, original job/source IDs, outputs, costs and selected/rejected status. Keep direct generations and cloud project placements distinct. On uncertain submissions reconcile the original job/request instead of generating again. None of that provenance is automatically supplied to the local warehouse simply by using Higgsfield.

Verified versus untested

Verified by live read calls: website categories; no owned websites listed; no 3D Jutsu projects listed; the current /3d-jutsu, /3d-jutsu/references/animation-audit and /3d-jutsu/references/location-new-angles instructions.

Verified by exposed tool contracts/local source: the website/app/game types and code/deploy lifecycle, Canvas operations and pricing dry-run, typed media-project placements, genuine GLB/Blender retrieval, scene/runtime constraints and paid render-conditioned image/video paths. The installed website skill was read for research; its build workflow was not activated.

Not exercised: cloud build/deploy, game scaffolding, board creation/graph execution, scene creation/import/edit/render/export, generation quality, model asset coverage, download fidelity, account-specific eligibility or cost for those actions. All recommendations above are implementation choices inferred from verified capabilities, not delivered new creative work.
